03 / METHOD

The build protocol

Clarity before complexity.

A transparent four-stage process keeps the work tied to the outcome it is meant to create.

  1. 01

    Diagnose

    Define the user, the real problem, the current workaround and what success would change.

  2. 02

    Scope

    Choose the smallest coherent version and make the trade-offs visible before building.

  3. 03

    Build

    Create the experience in working increments, testing behaviour on real screens and constraints.

  4. 04

    Learn

    Measure what people do, fix what blocks them and use evidence to decide the next version.

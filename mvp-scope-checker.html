        How to use the result

        An MVP is a test, not a small version of everything.

        The score is a simple planning signal, not market validation. Its job is to expose scope and risk before those decisions become expensive.

        Start with one user

        A specific first user makes the problem, workflow and distribution easier to test. “Everyone” cannot give you useful product evidence.

        Keep one outcome

        The first version should prove that one meaningful outcome improves—not demonstrate every direction the product could eventually take.

        Earn complexity

        Accounts, payments, live data and AI can be necessary, but each should enter version one because the test requires it, not because mature apps have it.

        Need a second pair of eyes?

        Turn the brief into a realistic build plan.
